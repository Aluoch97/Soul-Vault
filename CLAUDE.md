## How it fits together
- `src/app/` — the whole client, kept in labelled parts (was one 7.7k-line `src/App.html`). `index.html` is the page (head, markup, small inline scripts) with `@@include css/<file>` / `@@include js/<file>` lines; `css/NN-*.css` the main styles; `js/NN-*.js` the app script. `build_app.js` joins them in the order `index.html` lists them into the same single `<script id="sv-app">` and `<style>` as before, so every function and variable is shared. **The ORDER matters**: later code wraps earlier functions (`__renderVault`, `__closeModal`, `__updateNow`) and constants must exist before use, so add new code at the right place, not at random. A new part = create the file with the next number and add its `@@include` line; the build refuses a part nothing includes. Owner edits go here. Where things are (js): `01-boot-and-helpers` (state, transport, accessors), `02-init-routing-chrome` (`init`, routes, `renderChrome`), `03-home-tour-press`, `04-library-shelves`, `05-vault-and-studio`, `06-owner-tools-and-release-page`, `07-covers-player-and-details`, `08-comments-upload-now-playing`, `09-club-letters-new-release`, `10-release-extras-and-song-covers`, `11-chapters-lyrics-and-sync`, `12-series-backup-and-listens`, `13-editors-and-genres`, `14-library-data-and-lore`, `15-playlists-and-sections`, `16-deleting-notes-and-extra-covers`, `17-youtube-video-queue-and-diagnosis`, `18-settings-pages` (dresses the Settings pop-ups as full pages), `19-play-and-startup` (must stay last: it ends with `init();`).
- `apps-script/` — the backend, unchanged: `Vault.gs`, `MusicVaultImporter.gs`, `Lame.html`. Lives in Nick's Apps Script
  project (Sheet "Music Vault" + Drive). Deployed as a web app; the site talks to it with `fetch` POST (`doPost`, whitelisted list).

## Edge backend (moving off Apps Script, stage 1, Nov 12, 2026)
Plan: replace Apps Script with Cloudflare in stages (1: reads from a copy in D1; 2: Studio and all owner edits on the new backend; 3: covers/photos off Drive to R2; 4: plays, comments, sign-ups, then switch Apps Script off). Apps Script stays the place where data is edited until stage 2.
`functions/api.js` is `POST /api` (same `{fn, args}` shape as Apps Script, so the app barely changes). Today it answers only `getShare` (the slow call) from the D1 copy and keeps the built answer 60 s in the edge cache (`caches.default`); every other call is forwarded to Apps Script, and any error also falls back to Apps Script. `functions/_lib/share.js` is the port of `findShare_/shareScope_/shareBody_` from Vault.gs; `functions/_lib/mirror.js` stores the copy in the D1 table `kv` (chunked JSON).
The copy is filled from Apps Script's `getLibrary` using the owner key kept as the Pages secret `OWNER_KEY` (not in the repo); it refreshes itself in the background when older than 5 min, or on demand with `edgeSync`. `edgeStatus` (no key needed) shows whether the DB binding and secret exist and how old the copy is. The birthday is kept only to work out ages and is never sent to fans.
Bindings are set in the Cloudflare dashboard / API, not in a wrangler file: D1 binding `DB`; secret `OWNER_KEY`. Without them /api just forwards to Apps Script.
ON since Nov 12, 2026 (D1 database `soul-vault-db`, binding `DB`, secret `OWNER_KEY` set; live check: edge answer identical to Apps Script, 28 releases / 303 tracks / 406 versions copied). Switch: `site.config.json` `"edge": true` makes the app call `/api` (`SV_BOOT.api`); `SV_BOOT.gas` is always the Apps Script address, used if `/api` fails (`runFetch`). `node tools/edgecheck.js <base> [ownerKey]` compares `/api` with Apps Script for the public link (must say SAME). Not served at the edge yet: `getHome`, `getCover`, `prepareAudio`, all writes, plays, comments.

After any library-changing call that Apps Script accepted (`LIB_WRITES` in `functions/api.js`), the edge refreshes its D1 copy within seconds (`syncMirror(env, false, 8000)`, skipped if a refresh ran in the last 8 s) and drops its kept answers, so edits made in the old editors show at once instead of after up to 5 minutes. Sheet tabs on Nov 12: Releases, Tracks, Versions, Extras, Playlists, Shares, Settings, Comments, Listens, Errors, Needs Review.

## Studio (stage 2 start, Nov 12, 2026)
Owner-only screen (Settings > Studio, `renderStudio/drawStudio`): pick a release; edit info (title, type, tagline, story, mood, color, recorded at, artist, series, credits, hidden, unreleased), streaming links + "first appeared on", and every song (title, artist, features, producer, engineer, music video link, slowed+reverb video link, unreleased).
Backend: `functions/api.js` `studioGet / studioSaveRelease / studioSaveTrack / studioSaveLinks` (owner key checked at the edge against the `OWNER_KEY` secret; inputs cleaned in `functions/_lib/studio.js` with the same limits as Vault.gs). Fields that exist in the Sheet (titles, info, credits, song fields) are written THROUGH to Apps Script's `saveTracklist` (empty list, so no renumbering) / `saveWorld` / `saveTrackDetails`, then patched into the D1 copy at once; the Sheet stays the book of record for them until the cutover. New things with no Sheet column live only in D1 (`kv` key `overlay`): listen links + first appeared, slowed+reverb video per track, and unreleased flags (which win over the Sheet's). `getOverlay` (public) returns the overlay; `getShare` adds `overlay` and the merged unreleased flags (`overlayFor`, `shareBody(…, ov)`); the app reads them (`applyFlags`, `S.links`). `public/links.json` is now only a fallback.
Never use `saveTracklist` with a song list from Studio: it renumbers songs 1..n, and album credits refer to those numbers. Still not in Studio: lyrics, covers, audio files, extras, playlists, shares, hiding single songs.

Owner password: Settings > "Set owner password" (`setOwnerPassword`, needs the owner key once) stores a salted PBKDF2 hash in D1 (`kv` key `owner_pw`, `functions/_lib/auth.js`); `soulnicolas.com/admin` (`renderAdminLogin`) calls `ownerLogin(password)`, which returns the owner key to the browser (saved as `sv_owner_key`, like `?k=`). Five wrong tries from one address lock it for 15 minutes. "Sign out on this device" removes the saved key. The key itself still exists (Apps Script and the edge use it); the password only saves Nick from handling it. Passkeys (Face ID) would be a later upgrade.
Before pushing anything in `functions/`, run a real build (`npx wrangler pages dev dist` from a scratch folder, or `wrangler pages functions build`): `node --check` does not catch duplicate names across imports, and a broken Functions build fails the whole deploy.

`build.js` puts a fingerprint of the app code in the script address (`/app.js?v=<build>-<hash>`), so each deploy is fetched at once; before this (Nov 12) browsers kept the old `app.js` for hours and new buttons did not appear without a hard refresh.

## Uploads without Google Drive (stage 2 of the Sheet/Drive exit, Nov 12, 2026)
Studio (Settings > Studio) can create releases and add songs, photos and covers with no Drive and no Sheet. Files go from the browser to `PUT /upload?key=...` (`functions/upload.js`, header `x-owner-key`, R2 binding `MEDIA` = bucket `soulvault-media`, set on the Pages project via the API). Only two key shapes are accepted (`img/<id>/<t|160|400|1200|1600>` pictures; `<release-slug>/<name>.<mp3|m4a|aac|ogg|wav>` songs), an existing object is never overwritten (409), body max 95 MB. WAV/AIFF/FLAC are turned into a 256 kbps MP3 in the browser (`toMp3`, lame) first; masters stay on Nick's drive. Pictures are resized in the browser (covers `t`+`1200`, photos `160`+`400`+`1600`).
Records made this way are "native": they live only in D1 (`kv` key `native`: releases, tracks, versions, extras; `functions/_lib/native.js`), are added on top of the Sheet copy by `mergeNative` (so the 5-minute refresh never loses them), and are edited at the edge only (no Apps Script write-through). Studio fns: `studioPlanUpload` (picks the key), `studioAddSong`, `studioNewRelease` (starts hidden), `studioSetCover`, `studioAddPhoto`; for rows that come from the Sheet, a new cover and a new "plays first" version are stored as overlay overrides (`overlay.cover`, `overlay.primary`). A native version has `audio: "r2:<key>"` and `url` = `https://media.soulnicolas.com/<key>`. The owner's `getLibrary` goes through the edge, which adds the native rows, so the app sees them. The old Drive upload path (`getUploadTicket`/`registerUpload`) is used only when the edge is off.
Still on Drive/Sheet: the 256 older songs' own records, lyrics, playlists, shares, comments, plays, errors. Next: move those editors to the edge, then the cutover (stop reading the Sheet).

## Areas Cloudflare owns instead of the Sheet (Nov 12, 2026)

Switching refreshes from the Sheet, copies that area into D1 (`kv` key `owned`, `functions/_lib/owned.js`) and sets its flag; from then on `applyOwned` puts the owned data on top of every library answer (public `getShare` and the owner's `getLibrary`), the Sheet's copy of that area is ignored (left untouched as a backup), and the edge answers these calls itself (`OWNED_FNS`): savePlaylist, deletePlaylist, getPlaylists, addExtra, updateExtra, deleteExtra, saveLetter, saveBio, saveArtistLinks.
